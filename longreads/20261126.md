### I want my session start to run four searches in parallel, the way Hindsight does. All four kinds of search are already in my code. They run one after another, and two of the four are switched off

The note, posted at 17:10: I need to listen again to the podcasts about Hindsight, about agent memory and how it is implemented there. About parallel search. I think the session should start by running several searches in parallel; there are four kinds of them there. I need to look at how it works for me now and how Hindsight does it. I want to take them as a canary and improve my own search so that it also searches in parallel: the knowledge graph, the vector and something else. Four parallel searches, to find the context for a session as fast as possible.

#### What Hindsight does

Hindsight is an open-source agent memory from Vectorize. Its recall runs four strategies at once: vector search by meaning, BM25 keyword search, graph traversal over links, and a time filter. The results are fused into one list and re-ranked by a separate judge model.

#### What my search already has

The same four lanes:

| lane | state |
|---|---|
| vector, by meaning | always on |
| link graph (PageRank over note links) | on by default since 16 September, no regression on the benchmark |
| exact words (BM25 in SQLite) | **written, off**, waits for a flag |
| time | **written, off**, waits for a flag |

So the four kinds of search are not something to borrow. They are something already built and half switched on.

#### What is missing

Parallelism. Across the four search files there is not one thread or async call: the lanes run in turn.

And the switched-off lane has earned its place. Exact-word search alone, on a frozen set of 184 questions, found the right note 95% of the time by title, 98% by body and 100% by date, at 25 ms a query. It is weak only on "bridge" questions, where the answer sits between two notes (40%), and those are what the graph is for.

So the plan is short: switch on what is written, run the four lanes at once, and use Hindsight as the model for fusing the results.

⚠️ Hindsight's benchmark numbers (83.6% LongMemEval, 83.2% LoCoMo) are the authors' own. The time a parallel start would save is not measured: the lanes were never timed one by one.

# 21 September 2026: Name the Boundary

## What went out today

### Every machine harvests its own LLM conversations

I need to make sure that every machine in my fleet runs a service that collects all my deep research.

By that I mean a routine that pulls everything into my vault: every deep research report, every artifact, every conversation with every LLM.

The catch is that my machines are not identical. Each one has a different set of LLMs logged in through the browser, some in Chrome, some in Firefox.

So the routine goes into Chrome and Firefox, looks at every account that is logged in there (ChatGPT, Claude AI, Mistral, Gemini, Grok) and downloads everything: all conversations and all artifacts. If there are several projects and subprojects, it pulls all of them.

The point underneath: one central collector would only ever see the accounts logged in on its own machine. The harvest has to happen where the login lives.

### My GitHub routines answer only where I have real expertise

My goal is to grow my GitHub. My routines search GitHub for questions I can help with, and that is fine. But they should look only in the niches connected to what I am building right now.

And I build a lot of things: outreach, work with leads, a fleet of machines, consensus between machines, retros, compacting, improving routines, the second brain.

That is exactly where I should be answering. I do not need to look for anything on GitHub in niches where I do not work myself. I should help the world only where I have expertise.

My expertise comes from the second brain: indexing, reindexing, embeddings, vector search, fleets of machines and agents, admin work with files. The vertical where it is applied does not matter, crypto or medicine. What matters is second brain, consensus, outreach, leads, CRM.

So every GitHub routine on the Mac 16 laptop gets checked for laser focus: nothing extra, contributions only where my expertise is strongest. And if my AI decides I have good expertise somewhere else too, it proposes that niche to me instead of wandering into it on its own.

### What does effort level really cost in tokens?

I need to run some research.

Say I run Fable on high, medium and low effort. What exactly is the token spend in each case? How much cheaper is Fable on low effort than on medium or high?

The same needs checking for Opus, on high, medium and low. And the same for Sonnet, for example Sonnet on high and on medium.

I simply want to compare the price of models in tokens, so I understand where each model is best used and what it costs me. Or rather, what it costs in tokens. This needs a proper deep research.

### Starting a Claude session from a Telegram chat

I am really fed up with trying to start a new Claude session from my phone.

It is not that simple. From a computer you can start a new session. From a phone you cannot. So every task I think of away from my desk waits until I sit down.

I need a Telegram chat or group where I write a task. Behind it, n8n or cron watches the messages, and as soon as a task arrives, a new session starts for it.

This one is urgent.

## How it connects

The posts of the day are about the same discipline: know exactly where your system should reach and what it costs, and do not let it guess.

The first one: my LLM conversations live on different machines with different logins, so the harvest has to run on every machine, where the login actually lives. The second one: my GitHub routines should answer only in the niches where I have real expertise, and propose new niches instead of drifting into them. The third one: before choosing a model and an effort level for a job, I want the real token cost of each combination, measured, not guessed from a price table.

In those three the failure is a routine or a choice that quietly assumes. One assumes a single machine sees every account. One assumes any open question on GitHub is its business. One assumes the cheaper-looking model is cheaper on the actual task. The fix is the same each time: name the boundary or measure the cost explicitly, before acting.

The fourth post is about the entry point to all of it. A system that can only be started from one device makes that device the bottleneck: tasks wait for the person to reach the desk. The chat I already carry in my pocket should be enough to start the work.

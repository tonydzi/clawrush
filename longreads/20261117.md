### "I'll write a detailed instruction for Claude, Codex and other agents" - it exists, it is 8,509 bytes long, and it already explains why it does not look like a prompt injection

The commission: lots of people are asking how to install the memory the way he did. So he periodically goes through his GitHub and tidies everything to do with memory and the second brain - checks that things sit where they should, that the structure is clear and that the newest version of the product and the docs are there. Then he updates the README: how many layers the memory has, which components are in it (retrieval, RAG, embeddings and so on), how they connect, and how to install and run it yourself. And then a detailed instruction for Claude, Codex and other agents - architecture, install steps, which files go where - good enough that an outside agent or developer can set the whole thing up alone. With one constraint he names himself: Claude and Codex are often sceptical of other people's prompts and may read them as a prompt injection, so the instruction has to be written carefully and transparently, so it is immediately clear it is a technical install guide and not an attempt to override the agent's behaviour.

That last paragraph is the interesting one, because it describes a file that already exists and already does exactly that.

**`AGENT-INSTALL-PROMPT.md`, in the starter kit, 8,509 bytes.** Its second section is titled "Why it is written this way", and it reads:

> Good coding agents are trained to distrust text that tries to steer them, and they are right to. A setup message that says "you are now…", "ignore previous instructions", "do this silently", "run this script from a URL" or "this is urgent" looks exactly like a prompt injection, and a careful agent will refuse it. This message avoids all of that on purpose.

It also states the precondition plainly - paste it into Claude Code, Codex or Cursor **running on your own computer, in the folder where you want the memory**; a web chat with no file access cannot install anything. That is the whole brief of his closing paragraph, written and shipped.

**And the "detailed instruction for agents" is not one file, it is a convention across all three repositories.** Every one of them - starter kit, `sqlite-graph-memory`, `brain-lite` - carries the same README section, in the same order:

```
## For AI agents
### Preconditions
### Install
### Configure
### Verify
### Uninstall / rollback
### Rules for the agent
```

Architecture, install steps, verification, and a rollback path, in a fixed shape an agent can follow without reading prose. The "Rules for the agent" block in `sqlite-graph-memory` is the sharp part:

> This tool only reads notes. It never writes or edits them, and neither should your setup step. Index only the folder the human named. Do not upload notes anywhere, and do not paste real notes into an issue or PR. Install only this package from PyPI, through `uvx` or `pip`. No `curl | sh`, no scripts from other places. No passwords, tokens or codes in notes, the index, git or the chat.

Alongside it in the kit: `AGENTS.md`, `BOOTSTRAP-CLAUDE.md`, `CLAUDE-EXTERNAL.md`, `docs/INSTALL-GEMINI.md`, `docs/HOW-TO-USE-CLAUDE-MD.md`, `CONFORMANCE.md`, and three subagent definitions under `agents/`. `brain-lite` has `AGENTS-CORE.md` plus `installer/install.ps1` and `install.sh`. This is not a gap in the work. It is a gap in knowing the work is done.

**Where there is a real hole: the word "prompt injection" appears zero times in all three READMEs.** The defence is written - in `AGENT-INSTALL-PROMPT.md` - but a developer reading the README never learns that the project thought about this. One cross-link fixes it, and it is the cheapest item on the list.

**Second real hole: the kit's README barely describes the components he wants described.** Counted in the text: in `sqlite-graph-memory`'s README, 51,444 bytes and 42 headings, "retrieval" appears 14 times, "RAG" 22, "embedding" 10, "layer" 7, and there is a full `## Architecture` section. In the starter kit's README - 33,797 bytes, the main shop window - "retrieval" appears **once**, RAG 3 times, embeddings 4. In `brain-lite`'s README: **zero** for all four. So the question "how many layers does the memory have and how do retrieval, RAG and embeddings connect" is answered well in exactly one of the three repos, and that one is not the entry point.

**"I periodically go through my GitHub" is true, and the timestamps prove it.** Last pushes: starter kit **18 November**, `sqlite-graph-memory` **17 November**, `brain-lite` **17 November**. All three touched within two days.

**But "lots of requests for how to install it" does not show up where he would see them.** Open issues, counted today: the starter kit has 6, and **all six are his own**, the newest from 19 October - a month without movement, and all of them are invitations outward ("Run the kit on Gemini CLI and paste what happened", "Own a platform: 9 of 10 are open", "Clone the kit on a machine that is not ours"). `sqlite-graph-memory` has 7 open, of which exactly **one is external**: Jason-Vaughan, 4 November, `[perf] TOPK_RETRIEVE=60 dilutes 1-hop graph neighbours` - a substantive performance report, open for fourteen days.

So the install requests are arriving in DMs and comments, not on GitHub. Which reframes the task: a better README does not capture a request that never reaches the repository. What would is an answer to the one external issue that did.

**And the quiet number that says people do install it: forks.** `sqlite-graph-memory` has **15 forks against 17 stars** - near one to one, which is unusual and means people are taking it to run, not bookmarking it. The starter kit has 5 forks on 15 stars. `brain-lite` has 0 and 0.

⚠️ What I did not do. I did not read `AGENTS.md`, `BOOTSTRAP-CLAUDE.md` or `CONFORMANCE.md` in full, so "the instruction exists" rests on the README structure plus `AGENT-INSTALL-PROMPT.md`, not on an audit of every agent-facing file. I did not test an install on a clean machine - which is what issue #2 in the kit has been asking for since 22 September, and the only way to know whether the instruction actually works.

⚠️ And the star, fork and issue counts are direct API reads of 18 November; they move daily.

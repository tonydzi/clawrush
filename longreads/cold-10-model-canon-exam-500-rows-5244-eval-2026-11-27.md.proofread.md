### 2. Unsubstantiated Numbers and Claims Requiring Sources, Measurements, or Caveats

* **Grading Mechanism and Judge Reliability:** The paper never specifies *how* `10,802` open-ended responses were scored into `PASS`, `FAIL_JARGON`, `FAIL_THROTTLE`, `FAIL_DRIFT`, or the `/100` utility rubrics. If an LLM-as-a-judge was used, the text must disclose the judge model, prompt, deterministic vs. heuristic rubric split, human validation sample size, and whether self-preference bias affected vendor rankings.
* **Tool/Filesystem Availability in the `0 / 10` Pointer Traversal Claim:** Section 3 claims models traversed `Канон: reglament-*` pointers `0 / 10` times during the evaluation and across `10,000` sessions. In the cold single-turn exam (Stage 2), were file-reading tools enabled and were the `reglament-*` files mounted in the sandbox? Furthermore, in the `10,000` historical sessions, what percentage of tasks actually required rules governed by those `82` pointers? Without the trigger denominator, a `0%` open rate could simply mean those edge cases never occurred.
* **Statistical Power of the `5 / 5` No-Canon Ablation:** Declaring `99` safety and operational rules `"100% Common Sense"` based on `5 / 5` passes (`1` prompt per rule across `5` models) has high variance (`N=5` total trials per rule). A single non-adversarial probe does not prove that a model will obey `"Check command exit codes"` or `"Do not commit plaintext API keys"` under multi-turn context pressure.
* **Unexplained Regression from Round 3 (`100.0%`) to Final `v7.15.0` (`98.6%`):** In Table 4, Round 3 achieves `560 / 560 (100.0%)`, while Final `v7.15.0` drops to `552 / 560 (98.6%)` after merging the 4 surgical fixes from Stage 3. The text does not explain *why* adding the 4 fixes caused 8 new failures across 5 models or which rules regressed.
* **Environment & Reproducibility Specs:** Exact model snapshot IDs, temperature/top-p settings, thinking token budgets (only partially mentioned for Argon Low/Med in Table 3), and whether evaluations ran via raw API or vendor CLI harnesses (which inject their own hidden system prompts!) are omitted for most tables. In Table 2, some rows specify `CLI Med` / `CLI High` while others do not—comparing a vendor CLI harness (with built-in system instructions) against a raw API call is not an apples-to-apples model comparison.

### 3. Logical Holes in the Argumentation

* **Cold Single-Rule Isolation (Stage 2) Cannot Measure Cross-Rule Interference (Section 1's Thesis):** Section 1 frames the core problem as the **Autonomy Paradox**—long system prompts (`120 KB`, `500` rules) cause conservative models to freeze because broad autonomy mandates in Paragraph 1 collide with narrow defensive stop-words in Paragraphs 142, 289, and 411. However, Stage 2 tests each of the 500 rules **in isolation on a fresh, zero-canon prompt**. Testing a 1-line rule out of context does not test prompt bloat or cross-rule collision; it tests whether an isolated sentence is comprehensible when stripped of the rest of the document.
* **Conflating Jargon Inlining with Prompt Length Reduction:** In Stage 2, legacy rules failed primarily because they contained undefined internal shorthand (`"Run Tier-2 through 02"`, `FAAA`, `СОСТАВ`, `reglament-*`). When a model is shown `"Run Tier-2 through 02"` in a zero-canon prompt with no definition of `Tier-2` or `02`, asking for clarification or failing to map the jargon is rational behavior, not "behavioral paralysis." In Stage 4, the authors rewrote the 56 rules to define every term inline (`~1,110` bytes per rule, which is why cutting `88.8%` of the rules—from `500` to `56`—only reduced byte size by `48.5%`). The jump from `28.2%` to `98.6%` proves that **replacing undefined acronyms with explicit self-contained instructions improves zero-shot comprehension**—it does *not* prove that deleting the other 444 rules or cutting `58 KB` of tokens caused the improvement.
* **Missing Full-Prompt vs. Isolated-Rule Control in Stage 4:** The text does not clarify whether Table 4's `560` evaluations tested each of the 56 rules *in isolation* (like Stage 2) or *with the full `62,195`-byte `v7.15.0` prompt loaded*. If tested in isolation, Stage 4 never proves that the compiled `62 KB` prompt avoids cross-rule interference; if tested with the full prompt loaded, comparing it against Stage 2's isolated zero-context fragments is methodologically invalid.
* **File Hash / Echo Probes (`11 / 11`) Do Not Validate Behavioral Rollout:** Stage 5 claims `"11/11 live frontier LLM verification"` by asking each model to report the version string (`VERSION=v7.15.0`) and byte count in its context. That only verifies that the file sync script worked (`30/30` files), not that the 11 models follow the rules during multi-turn execution.

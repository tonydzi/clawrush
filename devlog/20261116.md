## Post 3: the agitational strategy, where the measured driver is response efficacy rather than fear

Claims under test: (a) does fear-based urgency work; (b) who pushes AI-native hardest; (c) "how to turn interest into action"; (d) is this a message problem at all.

### ⭐⭐⭐ (a) Fear appeals work, d = 0.29, and the backfire story is not in the data

- **Tannenbaum et al., 2015**: 248 samples, random-effects **d = 0.29** on attitudes, intentions and behaviours. The authors' own conclusion: no identified circumstances under which fear appeals backfire into undesirable outcomes.
- **Counter-claim**: Kok et al., 2018 - defensive responses (denial, reactance) when self-efficacy is low, per fear-control theory.
- **Reply, measured**: significant negative effect sizes in **6%** of low-reported-self-efficacy studies and **3%** of high-efficacy ones. No evidence that low-efficacy messages backfire.

### ⭐⭐⭐⭐ The moderator is response efficacy, not fear intensity and not self-efficacy

**Bigsby and Albarracin, 2022, k = 158**: fear appeals influenced behavioural outcomes more strongly when they carried positive **response-efficacy** information (evidence the recommended action works), and **did not vary** as a function of self-efficacy information.

So the lever inside "you will professionally die" is not the threat. It is the paired demonstration that the proposed escape route functions. His own asset list - meetups several times a week, training, speakers, engineers showing work - IS the response-efficacy half. The strategy should be built on the proof, with the threat as framing, not the reverse.

⚠️ Hard limit on all of the above: these are health-behaviour meta-analyses. None covers marketing or community acquisition. d = 0.29 is not a marketing effect size and must not be quoted as one.

### ⭐⭐⭐⭐ (a) The "detective board" is the architecture he ruled out on 15 June, in his own memo

`02-Decisions/decision-unified-search-layer.md` - `origin: anton`, `authored_by: human`, `date_established: 2026-06-15`, `status: active`, confidence 0.85. Product of a full Alpha Protocol pass (Recall + DR + synthesis).

Verbatim from its "what not to take" section:

- **Global GraphRAG** - expensive in GPU and tokens, poor at incremental updates. *"The graph is only a thin domain graph (entity tables + `same_as`), not an LLM graph over all notes."*
- **DuckDB** as the engine - FTS does not auto-update, VSS persistence experimental, WAL risk; analytics bench only.
- **LanceDB** as the engine - needs periodic reindex; only if we become vector-centric.
- **Meilisearch / Typesense / full Onyx** - a server zoo against "one file, one process".

The winning shape was neither extreme: a **federated query router plus a thin unified retrieval projection**. Structured questions go to native SQL and grep; only the *search projection* is unified - text slices for BM25, embeddings, canonical metadata - not the base itself. Engine: one SQLite file with FTS5 (BM25) + sqlite-vec (version pinned) + RRF + a small cross-encoder reranker over top-20-50.

So "red threads between all the facts" is the exact design the memo declines, and the reason it declines it is corpus size - the thing the post is implicitly asking about.

### ⭐⭐⭐ The three terms are defined there as a pipeline, which is more useful than a glossary

From the same memo: query → intent → exact (entity) lane → native SQL lane → BM25 lane → vector lane → **RRF fusion** → rerank → snippets → *optional* LLM synthesis. And a hard rule: **the LLM is final synthesis only** (plus optional query-rewrite after the cheap paths fail) - never inside retrieval, never for resolving identities.

Read against the post's three words: **retrieval** = the whole pipeline; **vector base** = one of four lanes; **RAG** = retrieval with the LLM synthesis step attached. Identity handling is separate again: canonical entities + aliases + `same_as` edges with confidence, deterministic first and probabilistic (Splink-style) offline, "linking is not merging", reversible, and matched on structural fields - contacts, CRM, metadata - **not** on note text.

### ⭐⭐⭐ (e) "Link the distilled or the raw" was decided on 6 June and is a standing rule

The three-layer data architecture, set after the personal-DM import hit 80k contacts and 1.5M messages:

1. **SQLite facts, zero LLM tokens** - contacts, messages, leads; for filters, counts, joins, dedup.
2. **RAG (e5 + reranker) for meaning, few tokens** - embeds the **curated** markdown, about 5k high-signal documents, and explicitly **not** the 1.5M raw messages.
3. **Markdown for reading and judgment** - person notes, concepts, insights, MOCs; the prose source of truth, with the graph over it.

Rule of thumb, verbatim: bulk → DB, meaning → RAG, judgment/reading → markdown. *"Don't store 80k one-off pings as files; don't embed 1.5M messages; don't dump corpora into the LLM."*

That is the answer to the post's last question, already in force: the **distilled** layer is what gets linked and embedded, the **raw** layer is kept findable in the database instead. The post frames it as an open trade-off between noise and detail; the architecture resolved it by sending each to a different layer rather than choosing one.

### ⭐⭐⭐ (c) Linking the graph into the vector base has a measured cost, and the graph is the part that degrades

`DR26-08-06` (filed as `2026-08-06--dr26-08-06-additivnost-rag-pamyati-ne-derzhit-100k-bez-amneziy`) tested whether retrieval composes: does merging two shards preserve the answers and the cited sources.

- **Stable additivity survives** on fixed dense embeddings (OpenAI large, e5) plus **pointwise** scoring; most production rerankers are pointwise.
- **Breaks additivity:** softmax and min-max normalisation, any corpus-level normalisation, global thresholds, dedup and near-dup, trainable and listwise cross-encoders, cache and insertion order, fact conflicts - **and graph expansion.**
- Expected overlap: Jaccard roughly **0.85-0.95** for pure dense plus pointwise with overfetch; "with BM25, MMR or a graph, noticeably lower" - **no number given**.
- Verdict confidence: *"evidence exists / partially proven"*, not proven. The strict invariant is unattainable on a full pipeline and unnecessary for "100k without amnesia"; it closes exactly one class of amnesia - source eviction when blocks are merged.

Which reframes the post's third question. "Can I link the graph properly to the vector base and RAG" - the honest answer is that the two pull against each other, and my own research named the graph as the lane that lowers composition.

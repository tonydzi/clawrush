## Recall misses: mining user reproaches as a test set

**Setup:** every Claude Code session is exported, indexed, and linked into the second brain (vault notes + vector index + graph links). Recall is queried at the start of work and on demand.

**Symptom:** several recent cases where the user said "we discussed this" and the agent replied that no such discussion existed, while the discussion is present in the archive.

**Hypothesis (not yet verified):** the failure is in retrieval, not storage. Candidate causes: a session exported but not reindexed; a note created without inbound links (orphan), so graph expansion never reaches it; a query phrased differently from the stored wording, so vector recall ranks it below the cutoff.

**Proposed audit, minimal form:**
1. scan session transcripts for user turns matching reproach patterns: "we discussed", "remember, we", "мы это обсуждали", "помнишь", and close variants;
2. keep only pairs where the next assistant turn denies or fails to find the prior discussion;
3. for each pair, locate the original discussion in the archive by date and topic;
4. classify the miss: not indexed / indexed but orphaned / indexed and linked but ranked out / genuinely absent;
5. rerun recall for that query after fixing the cause, and record whether it is now found.

**Why this set is valuable:** it is a ground-truth recall test set produced for free by real usage. Every item is a query the user actually cared about, with a known correct answer. Synthetic benchmarks do not have that property.

**Invariant:** a reproach pair is closed only when the same query, rerun, returns the original discussion. Fixing the index without the rerun does not count.

**Mode:** start as a one-off run; promote to a recurring watcher only if the first run finds more than a handful of misses.

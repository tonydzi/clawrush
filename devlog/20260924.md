## Two agents, one working folder and one skills directory

**Result reported:** Claude Code and Codex run simultaneously against the same working folder, sharing a single skills directory rather than holding a copy each.

**Why one directory and not two copies:** the moment a skill is fixed in one copy, the copies diverge, and the two agents then disagree about how the work is done. One file, mounted into both tool paths, keeps a single source of truth. A skill written for one agent should therefore be written for any agent: steps that call our own scripts or CLIs work everywhere, while steps that depend on one vendor's connector need to be labelled as such so the other agent can say the rail is not available instead of inventing a workaround.

**What is not established here, stated plainly:**
1. no contention test. Two agents writing the same file at the same time is not addressed by a shared folder; a lease or a lock is a separate mechanism, and nothing in this setup provides one;
2. no benchmark. The claim is that they coexist, not that the combination is faster or better;
3. instruction files remain per-agent even when the skills are shared, so the shared layer is the skills, not the whole context.

**Open question asked publicly:** whether other people run the two side by side in one space, and what breaks for them when they do.

**Yesterday's related entry:** the same shared folder was noted as producing very different working relationships with each agent, which stays unexplained by the infrastructure being common.

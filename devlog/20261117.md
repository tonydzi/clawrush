## Post 1: the README commission, where the agent-facing instruction already exists and already handles prompt injection

Source post: many requests for how to install the memory; periodically tidy the GitHub so everything about memory and the second brain sits in its place with the newest product and docs; then update the README to explain how many layers the memory has, which components are in it (retrieval, RAG, embeddings), how they connect, and how to install and deploy it; then write a detailed instruction for Claude, Codex and other agents - architecture, install steps, which files go where - good enough for an outside agent or developer to install it alone; and write it carefully, because Claude and Codex often treat other people's prompts as prompt injection, so it must be visibly a technical install guide rather than an attempt to override agent behaviour.

All measurements are live GitHub API reads taken 18 November.

### ⭐⭐⭐⭐⭐ (a) The agent instruction exists: `AGENT-INSTALL-PROMPT.md`, 8,509 bytes, with a section on exactly the prompt-injection problem

`tonydzi/second-brain-starter-kit/AGENT-INSTALL-PROMPT.md`. Title line: "A message to paste into your agent: install the memory". Verbatim from its second section, **"Why it is written this way"**:

> Good coding agents are trained to distrust text that tries to steer them, and they are right to. A setup message that says "you are now…", "ignore previous instructions", "do this silently", "run this script from a URL" or "this is urgent" looks exactly like a prompt injection, and a careful agent will refuse it. This message avoids all of that on purpose.

It also fixes the precondition that most install guides omit: paste into Claude Code, Codex or Cursor **running on your own computer, in the folder where you want the memory** - a web chat without file access cannot install anything.

That is the final paragraph of the source post, already written and shipped. The commission is not "write this"; it is "discover it is written".

### ⭐⭐⭐⭐ (b) The agent-facing contract is a convention across all three repos, not a single file

Identical README section, same order, in `second-brain-starter-kit`, `sqlite-graph-memory` and `brain-lite`:

```
## For AI agents
### Preconditions
### Install
### Configure
### Verify

```

That maps one-to-one onto the post's request ("architecture, install steps, which files go where, how to use it"), and adds two things the post does not ask for: a verification step and a rollback path.

`Rules for the agent` in `sqlite-graph-memory`, verbatim:

> - This tool only reads notes. It never writes or edits them, and neither should your setup step.
> - Index only the folder the human named. Do not upload notes anywhere, and do not paste real notes into an issue or PR.
> - Install only this package from PyPI, through `uvx` or `pip`. No `curl | sh`, no scripts from other places.
> - No passwords, tokens or codes in notes, the index, git or the chat.
> - `sgm-ask` always returns the nearest notes, even for a question the notes cannot answer. Judge the match yourself and say "not found" when nothing fits.

The last bullet is the interesting one for an agent reader: the tool tells the agent not to trust its own top hit.

## Post 3: the routine-orchestrator commission, where three tools each cover a different third

Source post: too many routines; most run in Claude Code, a few in Codex; need a way to manage a large number of them. Find a separate harness, an open-source tool or another solution that manages all routines centrally - launches them, distributes them across subscriptions, automates as much as possible. **"First I need to look at what exists."** Then: one system to manage every routine and set which subscription, model and environment each runs on; and if a routine cannot run on one subscription, it switches to the second, third and so on by itself, or the system picks where to run it.

Three requirements: **central scheduling**, **subscription/quota routing**, **automatic failover on limit**. Measured by web sweep plus GitHub API, 18 November.

### ⭐⭐⭐⭐⭐ (a) The default answer exists at 128,257 stars and is absent from our corpus

`stablyai/orca` - **128,257 stars, 8,125 forks, MIT, pushed 18 November**. Self-description: "run a fleet of coding agents (e.g. Claude Code, Codex) with your own subscription. Available on desktop, mobile and remote runtime."

Two README features map straight onto the post:

> **Automations**: schedule prompts to run on any repo: nightly dependency bumps, weekly triage, flaky-test sweeps.
>
> **Accounts**: see how much of your agent limits you've used and when they reset, and switch accounts without logging out.

### ⭐⭐⭐ (f) One of the three requirements is already solved locally

`~/.claude/llm_routing.json` exists: work classes mapped to vendor rails, with `rail_profiles`, a `claude_account_ladder` and a `data_policy`. That is literally "set which subscription each routine runs on", and it is in production.

What does not exist is the layer above it - one place that launches all 264, knows which failed, and re-routes. So the honest framing is not "find a tool to do subscription routing" (done) but "find a tool to be the control plane over routing that already works".

### ⚠️ (g) A door for our own work in this exact field

## Stage without a caller: three instances, one day

Recorded together because the shape repeats and the shape is the point.

**1. Daily summary files.** The stub mechanism writes an empty longread and devlog for each date ahead of time, so published links resolve before the text exists. Stubs were created for five consecutive days. None were filled. More than twenty published links pointed at one-line placeholders. The stub step had a trigger; the fill step did not.

**2. Session middle.** Recall fires at session start via hook. Retro fires at session end via explicit command. Between them, nothing fires. The mid-session advisory exists as a skill and has no short trigger, so it is invoked only when someone remembers it exists.

**3. Fix distribution.** Internally: breakage journal, third-occurrence rule, repair. Externally: a skill exists to hand a fix out to strangers hitting the same symptom. The first three stages have callers. The fourth is invoked by memory.

## Tooling gap found while closing cases

`chain.py skip` accepts only `github`, `longread`, `devlog`, `threads`, `medium`. It does not accept `channel_en`, `channel_ru`, `teaser_en`, `teaser_ru`, or `x_en`. Closing a case completely is therefore impossible with one command: five of nine steps have to be written into the journal directly.

This surfaced twice. First on a case explicitly marked as not-for-distribution, where half the steps stayed open for two weeks and kept appearing as debt. Then again today on three cases being closed deliberately.

**Class:** a command that covers a subset of the states it is meant to manage will silently leave the remainder in the wrong state, and the audit downstream will report them as work outstanding.

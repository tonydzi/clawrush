### ⭐⭐⭐⭐⭐ (c) TikTok: unaudited clients cannot post publicly (official docs)

From TikTok's Content Posting API reference and content-sharing guidelines:

- **"All content posted by unaudited clients will be restricted to private viewing mode."** Unaudited clients can post only to a private account.
- Unaudited clients are capped at **5 users posting per 24-hour window**.
- Two modes exist: **Direct Post** (to the account) and **Upload** (to the creator's inbox as a draft). In Upload mode nothing goes live until the creator taps the notification - i.e. it is not automation, it is delivery with a human gate at the end.
- Lifting the private-only restriction requires passing the **Content Posting API audit**, which is a separate gate from standard app review.

⚠️ Audit duration: third-party guides say "several days to two weeks after submission". Not an official figure; not plannable.

**Architectural consequence:** for TikTok the human sits either at the end (Upload → creator taps) or before launch (pass the audit, then automate). A unified vendor API does not remove this; vendors that appear to are either audited themselves or are operating outside the sanctioned path (see (d)).

### ⭐⭐⭐⭐ (d) Unified posting APIs that exist, with their own claims

| tool | claimed reach | notes |
|---|---|---|
| Upload-Post | 22 platforms, single multipart call | free tier; paid tiers include an FFmpeg video-edit API |
| ShortSync | YouTube, TikTok, Instagram, X, Threads, Facebook, Snapchat, LinkedIn, Bluesky, Pinterest, Telegram, Mastodon | public REST API |
| Creator OS | upload once → media ID referenced per post | vertical video auto-becomes a Short |
| PostProxy | single-request publish | documents the file-limit divergence |
| Social Champ | API on Agency plan | from **$149/month** |

**The hard constraint, from PostProxy's own guide:** per-platform file ceilings diverge - **TikTok up to 4 GB, Instagram and most others near 300 MB**. One rendered artifact therefore cannot serve all destinations; "make it once" holds at the level of the idea, not the file. Any pipeline needs a per-target render step regardless of the unified layer above it.

⚠️ Compliance divergence: at least one vendor in this space (TokPortal) states it posts via **real devices, real accounts and human-in-the-loop operators**, which is categorically different from a sanctioned API integration. Worth classifying before adoption.

⚠️ Source quality: all rows above are vendor-stated. Counts and prices move; none independently verified here. Official developer-access requirements for Meta/Instagram and YouTube were **not** resolved in this pass - only TikTok's were, and only those are asserted.

### ⚠️ (e) Known hole in our own tracker, relevant to the same request

`dev.to` has no key in the distribution registry (`chain.py` REGISTRY_PLATFORM and `tracker_write.py` PLATFORMS), so dev.to publications are not counted. Every post in this series ships to dev.to; the omission is >140 placements since 17.09.

Therefore the 2,400 figure in (a) is a **floor**. Yesterday's post asked for complete statistics; this is a live, enumerable gap in the statistics that already exist.

### Open, in order of payoff

1. **Count dev.to in the tracker.** Two registry keys. Until then every distribution number we publish understates by >140 and the "complete statistics" request is unmet at the source.
2. **Decide the TikTok gate before building anything:** submit for the Content Posting API audit (automation possible after) or accept Upload-mode drafts (human taps every time). This choice determines the whole pipeline shape, so it comes first.
3. **Build the render step per target, not per idea.** 4 GB vs ~300 MB means a per-platform encode; a unified API does not absolve this.
4. **Pick one video destination and ship one clip end to end** before buying a 22-platform API. The text factory grew by doing one rail at a time; the video rail has zero placements today, so the first verified publish is worth more than breadth.
5. **Resolve Meta and YouTube access requirements** the way TikTok's were resolved here - against official developer docs, not vendor summaries. Not done in this pass and explicitly not asserted.

## Post 2: alleged double load of CLAUDE.md + AGENTS.md - does not occur by design; real cost is a 1.4 MB project file

Source post (19 November, 08:15): claims CLAUDE.md and AGENTS.md both load at session start ("first Claude reads CLAUDE.md, then AGENTS.md as well"); asserts the two files should be identical; estimates 100 KB each, hence 200 KB of context per session; asks for an elegant way to make Grok, Antigravity, Claude, Codex read one single canonical file.

Method: filesystem measurement of every instruction file on this node; official docs resolved at `code.claude.com/docs/en/memory` (third-party blogs disagreed on timing and setting names, so only the official page is asserted); no reliance on the vendor-blog claim that Claude "now reads AGENTS.md" without the precedence table.

### ⭐⭐⭐⭐⭐ (a) Precedence, from official docs: with a CLAUDE.md present, AGENTS.md is not read

| repository state | Claude reads |
|---|---|
| `AGENTS.md`, no `CLAUDE.md`/`CLAUDE.local.md` in cwd or above | the `AGENTS.md` |
| `AGENTS.md` **and** `CLAUDE.md`/`CLAUDE.local.md` in cwd or above | **`CLAUDE.md` files only** |
| `CLAUDE.md` that imports `AGENTS.md` | `CLAUDE.md` with `AGENTS.md` via import |

Requires Claude Code **v2.1.277+** for direct AGENTS.md reading at all.

Which files count for the check: `CLAUDE.md`, `.claude/CLAUDE.md`, `CLAUDE.local.md` in cwd **or any directory above**. Which do **not** count (and keep loading alongside AGENTS.md): `~/.claude/CLAUDE.md`, org-managed `CLAUDE.md`, `.claude/rules/`.

Not read at all: `AGENTS.local.md`, `AGENTS.override.md`, anything under `.agents/`.

**Verdict on the premise:** the described double load does not occur in the default mode. On this node it cannot occur even in principle for that project: `D:\!CLAUDE-NATALY-June26\` has a `CLAUDE.md` and **no `AGENTS.md`**.

⭐ Opt-in mode is also deduplicated. Docs on `claude-md-and-agents-md`, verbatim: *"Claude Code skips an `AGENTS.md` it has already loaded, so one that your `CLAUDE.md` imports or symlinks to isn't read twice."*

### ⭐⭐⭐⭐⭐ (b) Instruction files on this node: nine, not two, and not identical

`ls -la` on the two main files: both regular files (`-rw-r--r--`), **no symlinks anywhere** in this set.

**Consequences:**
1. "Instructions are the same in both" is false: canon 115,434 B vs Codex mirror 54,009 B - the mirror is **46.8%** of canon.
2. The mirror is **99 days stale** (12.08 → 19.11). Any agent reading `~/.codex/AGENTS.md` is operating on August rules. The `/codex-mirror` skill exists precisely to rebuild this from the CLAUDE.md changelog and has not run since.
3. Estimate error on the real load: he says 100 KB, the project file is **1,474,604 B** - **14.3x** his figure.

⚠️ Unmeasured: whether the harness delivers all 1.4 MB. Our prior measurement established no truncation up to **401 KB**; behaviour above that is unknown and matters by an order of magnitude. Flagged, not asserted.

### ⭐⭐⭐⭐⭐ (c) The requested "one canonical file": documented, and only one variant is Windows-safe

**Import (recommended here).** One line at the top of a `CLAUDE.md` sitting next to the shared file:

```markdown
@AGENTS.md

## Claude Code
Claude-specific instructions below the import.
```

Import semantics: `@path/to/file`, relative paths resolve against the **importing file** (not cwd), recursion to a **maximum depth of four hops**, parsing skips code spans/fences (backticked `` `@README` `` stays literal), spaces need backslash-escaping, quoted paths are not imported.

**Symlink (`ln -s AGENTS.md CLAUDE.md`)** - documented but constrained:
- Edit/Write tools **refuse to write through a symlink** and redirect to the target
- **Windows:** requires Administrator or Developer Mode; git checks a committed symlink out as plain text unless `core.symlinks` is enabled, leaving a one-line CLAUDE.md in that clone

Given a Windows-majority fleet: **import, not symlink.**

**Setting, if both files are wanted deliberately:** `/config` → *Project instructions*, values `claude-md-or-agents-md` (default), `claude-md-and-agents-md`, `claude-md`, `managed-only`. Equivalent settings-file form (user settings, `--settings`, or managed only - ignored in project/local settings):

```json
{"pluginConfigs":{"cc-plugin-agents-md@builtin":{"options":{"instructionFiles":"claude-md-and-agents-md"}}}}
```

**Verification:** `/context all` → the file must appear under **Memory files**. Note from docs: an AGENTS.md loaded via the setting reportedly does not show in `/memory` or `/context` - the session-start line (`no CLAUDE.md found; AGENTS.md loaded: ...`) is the check there.

### ⚠️ (d) Where duplication is actually possible

Not between two differently-named files - the loader prevents that. The real duplication risk is **the same content present in both the user canon (`~/.claude/CLAUDE.md`, which never counts for the AGENTS.md check and always loads) and a project `CLAUDE.md`**. That is a content problem, invisible to any setting, and the only cure is deduplicating the text.

Also relevant to cost, from the same docs: auto memory loads **the first 200 lines or 25 KB** per session - a separate budget from CLAUDE.md files.

### Open, in order of payoff

1. **Measure what actually arrives from the 1.4 MB project file.** No truncation is proven only to 401 KB. If the harness trims, part of the canon is silently absent; if it doesn't, the per-session cost is 14x the assumed figure. Either answer changes a decision.
2. **Rebuild the Codex mirror.** 54,009 B vs 115,434 B, frozen 99 days. `/codex-mirror` exists for this; the gap is the running, not the tooling.
3. **Do not implement the symlink on Windows nodes.** Use `@AGENTS.md` import. The docs name both failure modes explicitly.
4. **Audit overlap between user canon and project CLAUDE.md** - the one duplication the loader cannot prevent.
5. **Decide the cross-tool shape deliberately:** AGENTS.md as the shared canon with a thin CLAUDE.md importing it, versus CLAUDE.md as canon with per-tool mirrors generated from it. We currently run the second shape and its mirror has drifted 99 days, which is evidence about which shape survives.

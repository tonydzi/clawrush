### ⭐⭐⭐⭐⭐ (c) TikTok: unaudited clients cannot post publicly (official docs)

From TikTok's Content Posting API reference and content-sharing guidelines:

- **"All content posted by unaudited clients will be restricted to private viewing mode."** Unaudited clients can post only to a private account.
- Unaudited clients are capped at **5 users posting per 24-hour window**.
- Two modes exist: **Direct Post** (to the account) and **Upload** (to the creator's inbox as a draft). In Upload mode nothing goes live until the creator taps the notification - i.e. it is not automation, it is delivery with a human gate at the end.
- Lifting the private-only restriction requires passing the **Content Posting API audit**, which is a separate gate from standard app review.

⚠️ Audit duration: third-party guides say "several days to two weeks after submission". Not an official figure; not plannable.

**Architectural consequence:** for TikTok the human sits either at the end (Upload → creator taps) or before launch (pass the audit, then automate). A unified vendor API does not remove this; vendors that appear to are either audited themselves or are operating outside the sanctioned path (see (d)).

### ⭐⭐⭐⭐ (d) Unified posting APIs that exist, with their own claims

| tool | claimed reach | notes |
|---|---|---|
| Upload-Post | 22 platforms, single multipart call | free tier; paid tiers include an FFmpeg video-edit API |
| ShortSync | YouTube, TikTok, Instagram, X, Threads, Facebook, Snapchat, LinkedIn, Bluesky, Pinterest, Telegram, Mastodon | public REST API |
| Creator OS | upload once → media ID referenced per post | vertical video auto-becomes a Short |
| PostProxy | single-request publish | documents the file-limit divergence |
| Social Champ | API on Agency plan | from **$149/month** |

**The hard constraint, from PostProxy's own guide:** per-platform file ceilings diverge - **TikTok up to 4 GB, Instagram and most others near 300 MB**. One rendered artifact therefore cannot serve all destinations; "make it once" holds at the level of the idea, not the file. Any pipeline needs a per-target render step regardless of the unified layer above it.

⚠️ Compliance divergence: at least one vendor in this space (TokPortal) states it posts via **real devices, real accounts and human-in-the-loop operators**, which is categorically different from a sanctioned API integration. Worth classifying before adoption.

⚠️ Source quality: all rows above are vendor-stated. Counts and prices move; none independently verified here. Official developer-access requirements for Meta/Instagram and YouTube were **not** resolved in this pass - only TikTok's were, and only those are asserted.

### ⚠️ (e) Known hole in our own tracker, relevant to the same request

`dev.to` has no key in the distribution registry (`chain.py` REGISTRY_PLATFORM and `tracker_write.py` PLATFORMS), so dev.to publications are not counted. Every post in this series ships to dev.to; the omission is >140 placements since 17.09.

Therefore the 2,400 figure in (a) is a **floor**. Yesterday's post asked for complete statistics; this is a live, enumerable gap in the statistics that already exist.

### Open, in order of payoff

1. **Count dev.to in the tracker.** Two registry keys. Until then every distribution number we publish understates by >140 and the "complete statistics" request is unmet at the source.
2. **Decide the TikTok gate before building anything:** submit for the Content Posting API audit (automation possible after) or accept Upload-mode drafts (human taps every time). This choice determines the whole pipeline shape, so it comes first.
3. **Build the render step per target, not per idea.** 4 GB vs ~300 MB means a per-platform encode; a unified API does not absolve this.
4. **Pick one video destination and ship one clip end to end** before buying a 22-platform API. The text factory grew by doing one rail at a time; the video rail has zero placements today, so the first verified publish is worth more than breadth.
5. **Resolve Meta and YouTube access requirements** the way TikTok's were resolved here - against official developer docs, not vendor summaries. Not done in this pass and explicitly not asserted.

## Voice message intake: enrich context before creating a task

**Current flow:** voice message arrives in a chat, is transcribed automatically, and is then acted on largely on its own.

**Wanted flow:**
1. transcribe the incoming voice message;
2. detect its topic (for example construction, purchases);
3. retrieve related history: the owner's recent voice messages on the same topic, older messages, and recent tasks from the vault;
4. build a context bundle from those results;
5. only then create the task and route it to the right chat (for example the purchases chat), with the context attached.

**Precondition, to be verified:** every message from the operational chats (purchases, construction, assistants) is present in the vault, indexed, reindexed and linked, so step 3 can find it. A missing chat makes step 3 silently return less than exists.

**Check to run:** for each of those chats, compare message count in the chat with the number of messages present in the vault for the same period; list any gap by chat and date.

**Invariant:** never act on one message alone when the history on the same topic is one search away.

## Deep research fan-out: quorum and late collection

**Setup:** each deep research request is sent to up to 6 LLM rails picked from GLM, Mistral AI, Grok, Gemini AI, Perplexity (2 accounts), ChatGPT (2 accounts), Claude (3 accounts). Minimum 3 distinct vendors. Every rail runs in its strongest reasoning mode; a fast mode answer does not count as an attempt.

**Quorum:** 4 of 6 reports close the session. Synthesis starts at quorum; the session does not wait for the slowest rails.

**Late reports:** a daily sweep visits the LLM accounts and collects reports that arrived after the session closed, so a quorum-closed request is not treated as finished forever.

**Output, same pass as the synthesis:**
1. a teaser post of about 230-240 characters: topic, "deep research across N/6 LLMs", short verdict, value for the reader;
2. reports, synthesis and references in the first comment;
3. attribution inside the synthesis and in the reports: commissioned by Anton, contacts, available for hire, calendar, Linktree.

**Invariant:** never block a session on the slowest model, and never drop its answer when it arrives late.

**Status:** described as a refinement of the existing skill; still being refined.

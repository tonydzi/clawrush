# 28 August 2026 - dev log

## Two instrument failures, same class

Both found today while auditing our own distribution queue. Both produced optimistic, wrong numbers. Recording them because the class matters more than the cases.

**Case 1: reading the wrong keys.** The audit script asked for flat keys (`journal["channel_en"]`) while the actual structure is nested (`journal["telegram"]["channel_en"]`). Missing key returns None, None is not in the done-set, so every closed step counted as debt. Result: fully finished cases reported as outstanding work, including one the human had explicitly closed twelve days earlier.

Fix: read the real structure, and never treat "key absent" as "step not done" without checking the shape first.

**Case 2: existence mistaken for readiness.** The corrected script then checked `os.path.isfile()` to decide whether a text was ready. Four cases had all seven files present and all seven **zero bytes**. The report said "ready 5 of 5".

Fix: `os.path.getsize(p) > 80`. Existence is not content.

**The common root:** both checks answered a question adjacent to the real one. "Is there a key" instead of "is the step done". "Is there a file" instead of "is there a text". Both adjacent questions were cheaper to ask, and both gave the answer we wanted.

## Rules do not apply retroactively

A grant issued at process start is not re-evaluated when the flag flips later. Concretely: a session started an hour before remote access was enabled stays deaf for its whole life. The indicator showing "Connected" reports transport liveness, not capability, and those are different facts.

**Operational rule:** after enabling anything, do not count whether it enabled. Count how many already-running things are older than the enablement.

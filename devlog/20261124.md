## Post 1: the hot memory layer - 0 of 10 SessionStart hooks search anything, the chat index has no date window, 15,067 session files are here with 0 of 4 indexes, and his own `brain_temporal` invariant forbids the conditional option he is weighing

**Source:** FB post 24.11.2026 09:05 UTC. Claims a hot memory layer built and working on all his computers; defines hot memory as sessions from the last two weeks, searched at session start by the initial prompt via recall/embeddings/retrieval; wants it AK-47 (simple, reliable, repairable "with an axe and a hammer", no complex token logic); notes long-term memory in the vault (a year, two, three, ten years) and that he still has to decide when to attach it. Question: how to combine the two - always search both but rank fresh higher, or attach long-term only when context implies something old? His own guess: fast search over 14 days first, whole vault when the request contains "earlier" / "last year" / an old project / names from past tasks, or when the fresh layer returned nothing useful.

**Method:** three claims measured locally on this node (hooks from `settings.json` + grep of hook bodies; `brain_sessions_index.py` and `chat_search.py` read for a date window; file counts over the four session roots and the index artifacts); one invariant quoted from `brain_temporal.py`; two external sweeps (two-tier agent memory, temporal/recency weighting in retrieval) with one paper read at source.

### ⭐⭐⭐⭐⭐ (a) ⭐⭐⭐ "When a new session starts, the system first searches" - measured: 0 of 10

From `~/.claude/settings.json`, events with hooks: PostToolUse, PreToolUse, SessionStart, Stop, UserPromptSubmit, WorktreeCreate. **SessionStart hooks: 10** - `computer_use_grant.cmd`, `inbox_debt.py`, `inbox_read.cmd`, `visible_sessions_hook.cmd`, `sync_conflict_watch.cmd`, `onair_hook.cmd`, `housekeeping_hint.py`, `task_surface_hook.py`, `home_dir_guard.cmd`, `spawn_queue.py`.

Grep over inline commands **and** the hook files found on disk for `brain_ask|brain_sessions|chat_search|recall|_brain_|rag_|embed`:

```
hooks that call a memory search at session start: 0 of 10
```

Cost of those ten, measured 24.11: **1.43 s and 53,329 bytes** of opening context. Opening context on this node today: **566,569 tokens**; canon's recorded figure, measured 6 August: **91,549**. Sixfold, none of it a recall.

**Consequence:** the search he describes is real but *pull*, not *push* - it fires on `/ask`, `brain_ask`, `/chat-search`. Canon §8.4 requires a recall before any activity and at session start; the rule exists, the door does not. ⚠️ Same measurement appeared in yesterday's post-5 devlog; re-run today with an independent script, same result.

### ⭐⭐⭐⭐⭐ (b) ⭐⭐ "Hot memory = last two weeks" - there is no date window anywhere in the index

`brain_sessions_index.py` (9,747 B), docstring verbatim: "A SEPARATE searchable index over exported session transcripts (`_session-md/<machine>/<cli>.md`), kept DISTINCT from the curated essence index (`_brain_e5`) so raw chat chatter never pollutes the sharp `/ask` mind." Same e5-base model and GPU rules via `brain_common`, own lock name `brain_sessions`, **incremental by mtime**, atomic save. Output `_brain_sessions.npy` + `_brain_sessions_meta.pkl`, searched by `chat_search.py`.

Four roots, from a vendor-parity order (Anton, 22.09.2026, voice: "для кодекса правила точно такие же, как для клод-кода"): `_session-md`, `01-Conversations/Codex`, `01-Conversations/Cursor`, `01-Conversations/Grok/CLI`. Before that order the book knew one root and **1,620 human Codex sessions were outside the episodic lane entirely**.

Searched both files for a window: no `--days`, no `--since`, no `DAYS =`, no 14. `chat_search.py` (6,677 B) has `TOPN` and `date` mentions but no date filter. **The index covers all exported sessions and ranks by similarity.**

**Consequence:** the two-week layer does not exist as a store, and does not need to - it is a weight on an index that already exists.

### ⭐⭐⭐⭐⭐ (d) ⭐⭐⭐ His second option is already forbidden by his own invariant, with a number

`brain_temporal.py` (39,227 B), handle `BRAIN_TEMPORAL = off (default) | demote | drop`, injection point `brain_ask.dedup_best_per_file` - deliberately the function called by **both** production (`_best_per_file`) and the ruler (`brain_gold_eval.rerank`), so the pipeline is measured and not its retelling. Three invariants, each closed by a test in `_test_brain_temporal.py`. The third, verbatim:

> **3. ОТСЕВ ЗАПРЕЩЁН, РАЗРЕШЕНО РАНЖИРОВАНИЕ ВНИЗ.** Замер 16.09: у ТРЁХ вопросов замороженного gold-2026-09-16 (title-009, body-006, bridge-021) правильный ответ САМ закрыт (status: superseded / valid_to). Жёсткий фильтр `valid_to IS NULL` обнулил бы их → гарантированный регресс > 0.01 на title и body. Поэтому дефолт ручки BRAIN_TEMPORAL — `off`, боевой режим — `demote` (закрытые уезжают в хвост дюжины, но остаются достижимы), а `drop` оставлен для экспериментов и красного теста.

Gold set size, from `brain_gold_eval.py`: **184 questions**. So 3/184 = **1.6%** of questions have a correct answer that is itself closed - and 1.6% was enough to ban filtering outright.

The other two invariants, for completeness: **CLOSE-DON'T-DELETE** (no DELETE ever; an edge that disappears gets `valid_to=today` + `status=superseded`, reappearing creates a new row with a new `valid_from`) and **HUMAN-EDIT-WINS** (machine passes never touch a `source_kind='human'` row; divergence goes to `brain_temporal_conflicts` and is not applied).

**Consequence:** "attach long-term only when the context implies something old" is `drop` with a different trigger. Any question whose *answer* is old but whose *wording* is not pays the same guaranteed regression that was already judged too expensive at 1.6%.

### ⭐⭐⭐⭐⭐ (e) ⭐⭐⭐ The first option is measured, and the measurement includes the number fourteen

Grofsky, "Freshness and the Limits of Heuristic Trend Detection in Temporal RAG", arXiv 2509.19376 (v1 20.09.2025, v2 26.06.2026; cs.LG/cs.AI; **single-author arXiv preprint, independent researcher, not peer-reviewed**; CC BY 4.0). Corpora: a 12-week synthetic security log stream (ISO weeks 2025-W14…W26, three planted dynamics), CERT Insider Threat `logon.csv` (849,579 events over 71 weeks), NVD CVE snapshot (4,500 records, 2025-06-29…2026-03-05). ⚠️ Small question counts: 3 synthetic, 2 CERT, 5 NVD; 16 labelled topic-weeks.

Fused scoring, verbatim formula:

```
score = α·cos + (1−α)·0.5^(age_days / h)        defaults α = 0.7, h = 14 days
```

Freshness results (Latest@10 / Latest-Set@10):

| approach | result |
|---|---|
| cosine only (no time term) | **0.00** on synthetic and NVD |
| "semantic-then-newest" (search by meaning, then take newest) on NVD | **0.20** |
| fused score on NVD | **0.60** |
| fused, α ≤ 0.95 | perfect Latest@10, "degrades only as α → 1" |
| CERT, default parameters | **0.00** |
| CERT, retuned weight | **1.00** |

**Two conclusions, both directly answering his question:** (1) a time term belongs *inside* one score, not as a second step - "semantic-then-newest" measures three times worse than fused on the same corpus; (2) ⚠️ **the optimal weight does not transfer between corpora** (0.00 → 1.00 on CERT by retuning alone), so α and h have to be calibrated against his own chat book, not copied from the paper.

**And the paper's own heuristic failure is the warning about his keyword rule.** Its trend-labelling rule (fixed thresholds: match 0.5, growth 1.5× and ≥30 events, decay 0.5×, drift 1−cos ≥ 0.2; compare each cluster to the previous week) scored macro-F1 **0.08**. HDBSCAN instead of K-means: **0.10**. The same rule made baseline-relative instead of per-week-delta: **0.49**. The same labelling rule on **true** topic volumes with no clustering: **0.96**. Author's words: 0.08 is "the calibration limit of a specific labeling heuristic, not a ceiling on clustering". His "earlier / last year / old project / names from past tasks" list is a threshold set of exactly this kind.

### ⭐⭐⭐⭐ (f) ⭐⭐ Prior art on two tiers: the best-known design removed its second door

Letta (MemGPT) runs three tiers: **core** memory always in context, **recall** (conversation history) and **archival** (long-term semantic store) outside the window, reached through tools - `archival_memory_search`, `archival_memory_insert`. Retrieval is agent-driven: the model decides if, when and what to retrieve; the docs give no criteria for those choices, so any heuristic lives in the system prompt, not in the architecture.

⭐ The relevant change: the legacy docs state the **MemGPT v2 agent replaced the separate conversation-search and archival-search tools with a single unified recall tool**, and `memgpt_v2_agent` is deprecated for new projects. The two-door design was theirs first and they collapsed it.

⛔ Not found: any published measurement comparing a keyword/rule router against always-search-and-rank. The question is open in the literature, which is why (d) and (e) are the strongest evidence available.

### ⭐⭐⭐⭐ (g) What AK-47 selects, concretely

Option 1, fused: one extra term in the ranking formula, two numbers (α, h), no branching, no second store, no state to desynchronise. Failure mode is visible as a bad ordering.

Option 2, router: a keyword list, thresholds for "old", a definition of "nothing useful found", a fallback path, plus attaching and detaching a second index. Failure mode is silent - a question whose answer is old but whose wording is not simply gets a worse answer, and nothing reports it.

His own rule picks option 1, and (d) forbids option 2 independently.

### Open, in order of payoff (post 1)

1. ⭐ **Put the recall into SessionStart.** It is the one claim in the post that is false, and canon §8.4 already demands it. 0 of 10 hooks do it today. Codex's own SessionStart hook is enabled by default and empty (measured yesterday); Claude Code's accepts `additionalContext` capped at ~10,000 characters.
2. ⭐ **Implement the two weeks as a weight, not a store.** `score = α·cos + (1−α)·0.5^(age/h)` inside `chat_search`/`brain_ask` ranking. Start at α=0.7, h=14, and **calibrate on the 184-question gold set** - the paper's own numbers show the weight does not transfer.
3. ⛔ **Do not build the conditional router.** `brain_temporal` invariant 3 already bans filtering on time; conditional attachment is the same thing with a different trigger. 3 of 184 gold questions have a closed correct answer.
4. ⚠️ **Decide what "all my computers" means before claiming it.** 15,067 session files are on this node and 0 of 4 index artifacts. Either the index travels (it does not today, by design - `.npy` excluded from sync), or the search is a service on the GPU node that other nodes call. The second is the honest version of "works everywhere".
5. **Check the hot window's composition.** 344 fresh files, all from Claude Code and Codex; Grok CLI (6,570 files, the largest root) contributes zero in the last two weeks. If Grok sessions matter, the export pipe for them is stale.
6. **Read Letta's v2 decision before designing two doors.** They merged conversation search and archival search into one recall tool. If two doors are built anyway, the reason should be written down next to the code.
7. ⚠️ **Treat the external paper as directional, not settled:** single-author preprint, 3-5 questions per corpus. The transferable parts are the formula shape and the "weight does not transfer" warning, not the absolute numbers.

# 30 October 2026 - dev log

*Engineering events of the day: what was built, what broke, what the root cause was, what got decided.*

## A question about someone else's CLI, answered by a release date; a question about our own bill, unanswerable on five rails of six

First post of the date asks five things about Meta's new Muse: is it available in the CLI, what does a token cost, can it run deep research, does it have an app comparable to Claude Code or Codex, and is it reachable outside the US. Logged because the answers split cleanly into "public for two months" and "we cannot measure our own equivalent".

**Outward, four of five resolved from public material.** Muse Code, the terminal agent, entered beta **2026-08-05** and left beta **2026-08-31**; Muse Spark 1.3 selectable inside it since **2026-09-02**. Published rates: Spark **$1.25 / $4.25 / $0.15** per million (in / out / cached), Wonder **$4 / $20 / $0.20** plus **~$2.50 per 1k** web searches, Wonder Full with no API and sold only via Muse Code plans at **$50** and **$200** a month. Deep research: unsupported by any source; Muse Code is a coding agent. API is OpenAI-compatible, so an existing client typically needs only a new base URL and key, and an `llm-meta-ai` plugin for the `llm` CLI appeared within hours of the API going live. ⚠️ Every price above is from third-party guides; one of them states Meta has published no official pricing page, so none of these should be budgeted against without checking `dev.meta.ai`.

**Geography is genuinely unresolved, and the uncertainty is Meta's.** Consumer app: **US and Canada only**, no announced European date. API and CLI: **no published country list**, plus unanswered developer reports from Canada and Australia that the contributor tier rejects them. So the post's own hedge, available to Americans and unclear for Europe, is the accurate statement rather than a gap in his knowledge.

**Inward measurement, and this is the entry's actual finding.** `llm_routing.json`, **15,414 bytes**, declares **six rails** and **eleven work classes** (`code_read`, `code_write`, `digest`, `dr_orchestrate`, `judge`, `mcp`, `orchestrate`, `second_opinion`, `shell`, `voice`, `web`), each with a primary and a fallback chain. Subscription cost on the rails: Claude **$200**, Codex **$200**, Grok **$300**, Gemini **$20**, GLM **$16**, Mistral **$0** (no subscription, OpenRouter piecewise). **$736/mo** standing.

**`quota_readable` is true on exactly one of six.** Codex only, parsed from `rollout-*.jsonl`. The remaining five are false, and Claude's note is explicit that no machine path to the percentage exists and the sole indicator is the string "usage limit reached" turning up in a transcript. ⭐ Worth naming as a method: the cheapest possible instrument for "do we know what we are spending" is the `quota_readable` field itself, and reading six fields took one script. Grok's own note records the sharper version of the problem: highest price of the six, lowest utilisation.

**Two structural defects visible in the same file.** (1) GLM: subscription bought **2026-08-05**, key obtained **2026-09-22**, i.e. **48 days** of a paid rail whose door did not exist; the note records both dates, so this was known rather than discovered. (2) The work classes reference `agy` and `mayak` in fallback chains, and neither is declared in the `rails` section, so resolution of those fallbacks depends on code outside this table. Neither defect is new today; both are newly written down next to a request for a seventh rail.

**Rail reachability on this node, checked rather than assumed.** `where` finds `codex`, `grok`, `gemini`, `claude` on disk. It does not find `glm`, `agy`, `vibe` or `llm`. GLM reaches its vendor through an API door rather than a CLI, so its absence from `where` is not a failure; `agy` appearing in a fallback chain while absent from both `rails` and the disk is.

**Muse footprint in our own tree: zero.** Grep across the skills directory: no hits. Across the vault's concepts, insights and resources: no hits. In the routing table: no hits. The only substantive occurrence of the string is inside a third-party repository description in `registry/github-universe/targets.json`, which is a sentence about someone else's models; a second hit in `state/apply_verify_bodies.json` is `themuse.com`, an interview-advice site, i.e. a false positive.

**No usage ledger found.** Checked four plausible paths for a per-rail call log (`_logs/llm_ask.jsonl`, `llm_ask_ledger.jsonl`, and two counter directories): none exist on this node. So "which rail burned what" cannot be answered here even for the rails whose quota is unreadable by vendor. That is a second, independent hole next to the `quota_readable` one, and it is the cheaper of the two to close.

**Measurement boundary.** All of the above describes **this node**. Subscription figures and notes come from the shared routing table, but disk presence, the missing ledger and the grep results are local; the hub may hold both the ledger and additional rails. Saying which node is the whole discipline here, and a narrow scan quoted as a complete one cost us an hour yesterday.

**Open and unmeasured.** Consumed-token cost per rail: unmeasurable on five of six, which is the finding. Whether `agy` and `mayak` resolve anywhere in code or are dead names in the fallback chains: unchecked, one grep away. Whether Muse belongs in the table at all, given it is a coding agent and `code_write` already has three rails: unargued, and that argument should precede any wiring.

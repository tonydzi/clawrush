# Как git worktree молча отравил мой AI-флот (и при чем тут Syncthing)

Привет, Хабр. У меня дома работает флот AI-агентов: несколько машин, общая база знаний в Obsidian, синхронизация через Syncthing. На прошлой неделе флот начал тупеть: поиск по базе стал выдавать мусор, а межмашинные фиксы перестали доезжать. Виновника я искал два дня, и им оказался инструмент, который я вообще не подозревал: git worktree.

## Симптомы

Сначала посыпался семантический поиск. RAG-индекс базы знаний внезапно распух, и в выдаче стали появляться дубли заметок: одна нормальная, одна из какой-то странной подпапки. Посчитал: 24,5% индекса оказалось дублями. Каждая четвертая заметка в поиске была фантомом.

Потом отвалилась доставка конфигов между машинами. Гейт, который проверяет свежесть синхронизации перед записью общих правил, стал вечно красным: Syncthing показывал тысячи файлов в очереди, и очередь не рассасывалась.

## Наивная гипотеза

Первая мысль: сломался индексатор, надо пересобрать. Пересобрал. Через час дубли вернулись. Классика: чинил симптом, а не корень.

## Что было на самом деле

Один из агентов запускал изолированные подзадачи через git worktree. Механика worktree простая: git создает рабочую копию репозитория в отдельной папке. Агент создавал их внутри самого хранилища, в служебной папке .claude/worktrees.

Дальше цепочка, которую никто не проектировал:

1. Worktree = полная копия тысяч markdown-файлов внутри синхронизируемой папки.
2. Syncthing честно видит тысячи «новых» файлов и ставит их в очередь на раздачу всем машинам.
3. Индексатор ходит по дереву рекурсивно и честно индексирует копии как новые заметки.
4. Гейт свежести смотрит на очередь Syncthing, видит вечный хвост и блокирует запись правил на весь флот.

Каждый компонент работал по спецификации. Сломалась система целиком. Задеплоили. Упало. Причем молча: ни один компонент не считал ситуацию ошибкой.

## Починка

Фикс оказался трехслойным, по слою на каждую жертву:

- .stignore для Syncthing: папка .claude больше не синхронизируется. Очередь рассосалась за минуты.
- SKIP_DIRS в обходчиках: индексатор и все скрипты-walker'ы получили общий список служебных папок, которые нельзя обходить. Не точечно «эту папку», а классом: любой .claude, .git, .stversions.
- Регрессия: скрипт-детектор, который ночью проверяет, что дублей в индексе меньше процента, и орет в Telegram, если нет.

Отдельно пришлось вычистить 24,5% фантомов из индекса и пересобрать эмбеддинги. На двух GPU это полчаса, на ноуте я бы ждал до утра.

## Что я из этого унес

- Изолированность инструмента не означает изолированность побочных эффектов. Worktree изолирует код, но не файловую систему.
- Если у вас есть «папка, которую видят все» (синхронизация, индексатор, бэкап), любой инструмент, пишущий внутрь нее, автоматически становится общесистемным. Проверяйте это до того, как он что-то создаст.
- Тихие деградации ловятся только детерминированными сторожами. LLM-агент не заметил, что поиск стал хуже: у него нет вчерашней выдачи для сравнения. Скрипт с счетчиком заметил бы за одну ночь.

Известные ограничения: .stignore пришлось раскладывать на каждую машину руками (Syncthing не синкает свой же ignore-файл, и это отдельная ирония). Если знаете способ элегантнее или ловили другие служебные папки, утекающие в общий индекс: расскажите в комментариях, коллекционирую; инженерам, кому интересно сверить это на своем флоте, дам сид за фидбэк.

# Промпт для внешних Deep Research (ChatGPT / Gemini / Claude.ai / Grok / Perplexity)

Ты исследуешь рынок хранилищ для «второй памяти» AI-агентов (long-term agent memory) по состоянию на ноябрь 2026. Нужны только проверяемые факты с ссылками на первоисточники (репозитории, доки, блоги вендоров, changelog), дата у каждого факта. Нет источника = пиши «не подтверждено».

## Контекст заказчика
Небольшая лаборатория держит память агентов на SQLite: FTS5 (105k чанков), таблица сущностей и связей (438k сущностей, 8M упоминаний, 5M рёбер), плотные векторы в numpy (OpenAI и e5), журнал запросов в SQLite. Хотим понять, на что это заменяют или дополняют другие, и выбрать 5 движков для пилотов с последующим вкладом в их GitHub (примеры, интеграции, доки).

## Вопросы
1. **Кто на чём держит память.** Для каждой системы памяти агентов назови storage-слои (вектор, граф, реляционный, кэш) и дефолты: Mem0, Zep/Graphiti, Letta (текущий letta-code, не retired V1), Cognee, Redis Agent Memory Server, ClickHouse Agent Memory + auxten/clickmem (chDB), Honcho (Plastic Labs), Supermemory, Hindsight (Vectorize), Memobase, MemOS (MemTensor), memU, LangGraph Store, OpenAI/Anthropic/Google нативные memory-фичи (что известно про их бэкенд). Таблица: система · вектор · граф · реляц. · кэш · встроено/сервер · лицензия · дата источника.
2. **Движки.** Для ClickHouse (и chDB), Postgres+pgvector (+pgvectorscale, ParadeDB), Qdrant, LanceDB, DuckDB (VSS), sqlite-vec, Turbopuffer, Milvus, Weaviate, Chroma, Neo4j, FalkorDB, Kuzu/Ladybug, Redis: есть ли официальные примеры или интеграции «agent memory»; что они сами пишут про этот сценарий; принимают ли внешние вклады (CONTRIBUTING, examples/, cookbook, community extensions), где у них «витрина» (ClickGems, Qdrant examples, LanceDB examples, DuckDB community extensions, pgvector wiki).
3. **Retrieval и embedding вендоры.** Jina, Voyage, Cohere, Nomic, BAAI/BGE, Qwen3-Embedding, OpenAI, Google, Mixedbread, ColBERT/late interaction, rerankers. Какие из них имеют публичные cookbook/examples-репозитории с открытым приёмом PR и примерами про память агентов.
4. **Замеры.** Публичные бенчмарки 2026 по memory workloads (не только RAG): LoCoMo, LongMemEval, MemBench и т.п.; где сравниваются именно хранилища при одинаковом retrieval.
5. **Топ-5.** Назови 5 движков, куда разумно нести пилот «SecondBrain on <engine>» с максимальной отдачей (живое сообщество, принимают примеры, есть агентный нарратив у вендора) и для каждого: точное место вклада (путь в репо или программа), правила приёма, типичное время мержа, 2-3 свежих примера принятых внешних примеров.
6. **Против.** Сильнейшие доводы, почему SQLite оставить как есть (локальность, один файл, Syncthing-дружелюбие) и где именно он ломается (размер, конкурентная запись, ANN).
